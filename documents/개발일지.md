### TCP 통신 구조 변경 — 클라이언트 → 서버

#### 변경 배경

기존에는 라즈베리파이(Pi)가 PC 프로그램에 능동적으로 TCP 연결하는 **클라이언트 구조**였다.
네트워크 환경 변경에 따라 Pi가 포트를 열고 PC가 접속하는 **서버 구조**로 전환하였다.
JSON 프로토콜 및 데이터 방향은 그대로 유지하여 PC 프로그램 수정을 최소화하였다.

#### 통신 구조 비교

| 구분 | 변경 전 (클라이언트) | 변경 후 (서버) |
|------|------------------|--------------|
| PORT1 (7000) | Pi → PC 서버에 connect | Pi가 listen, PC가 connect |
| PORT2 (7001) | Pi → PC 서버에 connect | Pi가 listen, PC가 connect |
| 데이터 방향 | Pi→PC: 센서 데이터 / PC→Pi: 제어 명령 | 동일 (변경 없음) |
| JSON 프로토콜 | — | 변경 없음 |

#### 수정 파일

**`source/client.py`**

- `UnitBoardGetStatus.run()` — PORT1 (센서 데이터 송신 채널)
  - `socket.connect(SERVER_ADDR)` 제거
  - `socket.bind()` + `listen(1)` + `accept()` 패턴으로 변경
  - 서버 소켓을 while 루프 외부에서 한 번만 생성하여 프로그램 수명 동안 유지
  - PC 연결 해제 시 자동으로 다음 `accept()` 대기 (재시작 불필요)
  - Exponential backoff 재연결 로직 제거 (서버는 수동 대기 방식)

- `TcpServerThread.run()` — PORT2 (제어 명령 수신 채널)
  - 동일하게 서버 소켓 패턴으로 변경
  - `socket_event.set()` (ProcessPoolExecutor 시작 트리거), I2C LED 제어, JSON 파싱,
    ACK 응답, 중복 데이터 감지 등 기존 로직 전부 유지

**`config/config.ini`**

```ini
# 변경 전
HOST = 192.168.100.5   # PC IP (연결 대상)

# 변경 후
HOST = 0.0.0.0         # Pi 바인딩 IP (모든 인터페이스에서 수신)
```

#### PC 프로그램 측 필요 변경 사항

PC 프로그램에서 아래 두 가지만 변경하면 된다:

1. PORT1(7000), PORT2(7001)를 `listen/accept` → `connect(Pi_IP, PORT)` 로 변경
2. 연결 대상 IP를 Pi의 IP 주소로 설정

JSON 포맷, 데이터 방향, 커맨드 체계는 **변경 없음**.
